# Spec Delta

## MODIFIED Requirements

### Requirement: TC1 系列与赛事基础资料
系统 SHALL 允许登录用户创建系列和赛事，服务端记录创建者为所有者。系列具有名称与说明；赛事具有名称、可选稳定游戏预设gameId、游戏分类game(card/fighting)、说明、线上/线下地点文本、可选ISO8601开始时间、可选同所有者系列及visibility(private/public)。名称为1–100码点、说明至多2000码点、地点至多200码点；文本按纯文本显示。新赛事默认private、runtimeStatus=not-started；实际配置草稿在配置页显式新建。用户可修改自有基础资料与公开状态，不得借此写运行状态、结构或他人所有权。

系统 SHALL 对已选择预设的赛事由服务端派生分类，客户端同时提供不一致分类时原子拒绝。新界面先选分类来筛选预设，再选择最终游戏；切换分类清空不兼容的旧游戏，按基本信息、比赛项目、时间与地点、归属与公开分组；保留明确的未指定游戏兼容项；未知gameId拒绝，旧记录缺少gameId按null显示，不猜测原记录的具体游戏。开始时间由日期时间选择输入并仍以ISO8601带时区请求、UTC时刻保存。

#### Scenario: 系列与两届赛事
- **WHEN** 同一所有者在系列中创建两届赛事
- **THEN** 两者有独立ID、版本和配置集合，修改其中一场不改变另一场

#### Scenario: 非法归属与持久化
- **WHEN** 请求关联他人系列或写入非法日期、字段或运行状态
- **THEN** 原子拒绝且返回可定位错误；合法创建的数据在服务重启后仍可读取

#### Scenario: 游戏预设创建与旧赛事
- **WHEN** 用户选择街霸六创建赛事，或编辑仅有card分类的旧赛事而未选择游戏
- **THEN** 前者保存街霸六gameId与fighting分类，后者保持gameId为空和旧分类；同键重试及旧账号所有权不改变

#### Scenario: 伪造游戏分类
- **WHEN** gameId不存在或街霸六被同时声明为card，或他人尝试修改游戏/时间
- **THEN** 返回可定位输入错误或原权限错误，不改变记录版本、结构及幂等结果


#### Scenario: 手机HTTP保存
- **WHEN** 用户通过普通HTTP局域网地址在手机宽度页面选择分类、游戏、时间并点击保存，浏览器没有crypto.randomUUID
- **THEN** 系统仍以安全随机请求键成功提交，保存后刷新仍有同一赛事资料和UTC时刻；请求键生成失败可读提示且解除保存中状态，幂等重试规则不变

### Requirement: TC2 公开目录与可见性
系统 SHALL 允许访客检索公开赛事，支持名称关键词、游戏gameId、游戏分类及分页；排序按创建时间倒序再按ID形成稳定次序，page从1开始、pageSize默认20且最大50。私有赛事仅所有者可读，其他用户读取返回404。公开系列只在存在公开赛事时可读取，仅暴露系列名称、说明及其公开赛事。公开状态不意味着报名或运行能力可用。

系统 SHALL 对同时提供的gameId与game分类按交集筛选，未知gameId为400错误，未指定游戏筛选只返回gameId为空的旧记录；所有筛选先保持公开范围和稳定分页顺序。

#### Scenario: 私有数据不泄露
- **WHEN** 访客检索或猜测私有赛事及无公开赛事的系列ID
- **THEN** 列表不包含私有记录，直接读取返回404，不泄露私有标题、配置或名单

#### Scenario: 公开详情部分不可用
- **WHEN** 公开赛事基础信息可读取，但对阵/排名后端未实现
- **THEN** 基础信息正常显示，对阵/排名模块独立显示能力错误，不把整页降级成空白

#### Scenario: 按游戏筛选
- **WHEN** 访客选择街霸六筛选，或选择未指定游戏
- **THEN** 前者只显示街霸六公开赛事，后者只显示未指定具体游戏的公开赛事；私有记录不出现在任何筛选中
