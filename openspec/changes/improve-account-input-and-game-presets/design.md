# Design

## Context

见proposal.md与research.md。上一轮实现已提交1db793a；正式AC1仍要求12–128位密码，TC1/TC2只有分类，日期是普通ISO文本输入。现有SQLite以JSON保存元数据，写操作通过版本、请求键和同步事务保护；身份由本地会话决定。新的规划不得修改已归档证据来声称反馈已修复。

## Goals / Non-Goals

**Goals:** 在原有身份、错误、持久化和配置闭环上减少表单负担；具体游戏与分类分离；资源展示和赛事业务解耦，允许素材不齐时如实交付状态。

**Non-Goals:** 此切片不迁移到外部认证，不新增邮箱/电话必填，不引入排程或外部日历同步，不实现角色/牌组赛果录入。游戏预设不提供任何新赛制运行；structure-v1/routing-v1及当前冻结锁定继续有效，实际配对支持集仍为空。

## Decisions

### D1 密码策略与既有身份

注册和登录都验证非空字符串，去除产品min/max长度以及sessions中的1024长度拒绝；不trim、不截断、不规范化用户密码，不变更现有摘要算法/参数和用户ID。所有请求继续由1MiB JSON限制、认证限流控制，不新增暗中的字符复杂度门槛。空密码注册422字段错误，登录沿用401统一凭据错误。短密码提高猜中概率这一取舍记录在评估中，不以此恢复用户已取消的限制。

继续保持本地认证可工作。Supabase Auth/Auth.js的评估输出是独立的账号迁移决策材料，比较密码策略、username/email映射、scrypt摘要迁移、现有ownerId稳定性、会话过期/退出、断网行为、配置成本和CommonJS兼容。官方Auth.js Express标记experimental，Supabase默认最短策略与此需求可能冲突；本切片不能直接替换。若未来选择提供方，另开迁移change，不把未知事项塞入本次“完成”声明。

### D2 日期时间组件与时区

计划使用Ant Design DatePicker showTime，中文ConfigProvider/dayjs locale，封装单一赛事日期组件，按需加载和适配现有CSS，不整体重写设计系统。替代方案为原生datetime-local；它体积小但跨设备呈现/时间与焦点行为差异较大，先用小范围兼容性验证记录是否适合当前依赖版本。

日期模型分为墙上日期时间、明确固定UTC偏移和原始UTC值。默认偏移UTC+08:00，支持15分钟增量的-12:00至+14:00；显示“固定偏移，不自动处理夏令时”。转换显式使用所选偏移，不能用浏览器new Date(不带时区串)猜时区。切换偏移保持同一时刻并更新显示；旧时间未编辑时提交原ISO，避免秒/毫秒精度丢失。清空提交null，非法日期保留输入并给出字段错误。后台日期验证继续作为最终边界。

独立手算例：2026-10-05 10:30 +08:00→02:30Z；2026-10-04 23:45 -04:00→2026-10-05 03:45Z。两组测试不以被测转换工具生成预期；另验闰日、月末、空值与已有毫秒。

### D3 游戏身份与旧数据

增加gameId:string|null，保留现有game作为分类，避免旧客户端与资料整体破坏。选择street-fighter-6时服务端派生fighting；shadowverse-original派生card。客户端同时给不一致分类则422，未知ID则422。新UI按游戏搜索/选择，不再要求同时选卡牌/格斗；未指定游戏兼容项可保留原分类。旧记录缺gameId读取为null，不批量猜测迁移；未知但历史已存游戏ID展示文字与状态，不丢弃记录。

目录增加gameId筛选，gameId=unspecified仅作为查询哨兵，不是可保存的游戏ID；与旧game查询取交集，未知ID400。排序/分页、private404/public管理403不变。变更gameId只是基础资料，不改冻结快照或规则，不产生报名/结果；现有版本与请求键覆盖新字段，旧幂等结果缺新增字段由客户端兼容读取，不重写旧请求指纹。

### D4 资源目录与访问

拟增加GET /api/games和GET /api/games/:gameId/resources，统一JSON错误契约；前者返回目录schemaVersion、catalogVersion、items，后者返回指定游戏的资料版本和实体/素材项，未知游戏404。首版使用审阅过的静态版本化清单，不在服务端逐请求抓取官网；没有证据支持把官网地址当公开API。前端新增游戏预设选择及样例资源浏览，不把图片作为游戏ID或表单值。

清单实体：id、gameId、kind(character/card/class)、sourceName/displayName、locale、edition、sourcePage、catalogVersion；素材独立assetId、role(avatar/portrait/card-art/class-icon)、status、可选url/localPath、尺寸、校验值、来源与分发说明。进化前/后使用明确variant，不覆盖卡ID。原版八职业与中立分开；不是完整图库。图片URL只来自审阅清单，拒绝把任意用户URL当可信素材。

优先具体样例来源核验后采用可说明分发方式的文件；不可用条目保留pending/missing。前端保留布局、alt和名字，有单独加载/失败/重试；目录失败仍保留旧游戏选择和当前表单，可读取已存赛事。头像/立绘失败不会使整张表单重新挂载。具体图片未核实前不承诺asset-ready。浏览器运行错误与本地目录API错误分别呈现。

### D5 并发、冻结与验收

元数据新增字段仍进入当前规范化请求指纹，同键同请求返回原结果，过期版本409且保留本地游戏与日期；比较服务器副本后需确认替换。资源目录只读版本更新不写赛事、配置聚合或成功幂等记录，不参与赛果确认。所有已冻结结构仍只读；不新增配对算法、下游推进或处罚语义。

验收覆盖密码1/12/129/1025字符和Unicode/空白原样；时间两个固定偏移与浏览器不同timezoneId；新/旧赛事与重启、游戏分类伪造、筛选私有数据；至少两类图片的404/403/超时及目录503，焦点与360/768/1440布局。最终运行已有42后端/25前端/8浏览器回归和新增场景，数量以实际执行为准。

## Risks / Trade-offs

- [取消长度会允许弱密码] → 保留限流、会话防护、无凭据日志，不增加未经用户要求的密码策略。
- [外部认证要求不同凭据或密码政策] → 本次仅评估，迁移独立规划，不能导致旧用户所有权丢失。
- [Ant Design新依赖影响体积/React版本] → 先验证准确版本、按需引入并记录构建体积和焦点行为。
- [固定偏移不等于地区夏令时] → 明确标注，不自动承诺全球地区日历规则。
- [素材未取得或源站失效] → 来源状态如实记录，文本回退和单独重试；未核实立绘不假报完成。
- [影之诗版别尚未回复] → 先按原版规划并显式留门槛；若选择Worlds Beyond，修改相关预设/职业/来源，再实施该资源切片。

## Migration Plan

先做密码独立切片，再日历输入，再gameId兼容API与UI，最后资源目录和样例。实施前备份非临时数据库；新字段只增不猜测旧记录，启动加载和GET兼容旧JSON；迁移失败不破坏原库。回退旧客户端仍认识分类与UTC时间，但旧密码前端长度校验可能挡住新短/长密码，不能只回退一端；回退必须同步提供取消长度的账号表单。认证提供方迁移和生产部署不在本切片。

## Open Questions

认证供应商仅作为研究输出，不阻塞密码、日期或目录实现。影之诗原版/Worlds Beyond问题已向用户提出；其答复是素材切片开始前的明确门槛，不将未回复视为已批准版别。具体素材文件与分发方式按research.md中的有限核验任务确定，未取得的项保留缺失状态。
