# 具名报名入口与单败运行

新版审批入口绑定冻结配置，entryRef 包含 configurationId、stageId、groupId、port、position；双败另有 positionKind。初始种子用于排序，入口位置是组内位置。相同组ID在不同配置中仍是不同入口。

在报名页选择审批配置、阶段/小组及种子或绝对席位入口，然后审批。后阶段直邀可以提前占用未被晋级路由预留的位置。审批配置切换期间暂停审批和锁名单；载入失败可重试，另一配置的已保存入口要求明确重新分配。

锁名单须齐满每个输入的直接席位及计划晋级席位，且所有显式入口属于同一冻结配置。开赛复验冻结结构和计划摘要；后阶段等所有来源组完成，合并晋级者与直邀者后整体创建，不创建部分目标。池链复核活动身份重复。公开运行数据不包含报名答案及用户ID。

single-cut-v2 已支持实际运行。8→4 为4场、8→1 为7场；12→3 使用三个独立4人树，共9场。Q>1显示资格集合，不把未交手者称为冠军。启用季军战仅用于Q=1且N≥4，8人共8场；决赛和季军战各自使用冻结BO，同一批次必须两场裁定齐备才确认。未启用季军战，半决赛败者并列第三。

每次裁定及确认继续要求当前权限和乐观版本。裁定人员不能确认批次；成功键重放仍检查当前授权。已确认比分锁定，推进、后继比赛、排名和幂等记录同事务保存。

目录及新冻结的runtimeReady按实际运行支持计算。历史冻结记录保留原字段；实际启动按冻结版本与计划重新检查。此切片只开放single-cut-v2；其他赛制等待各自运行验收。
