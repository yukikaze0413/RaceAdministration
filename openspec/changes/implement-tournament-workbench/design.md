# Design
## Context
复用现有React/Express/SQLite、structure-v1/routing-v1和配置服务。用户2026-10-07明确实施页面计划，采用已展示推荐范围，不重复审批阶段。
## Goals / Non-Goals
**Goals:** 精确权限、版本化报名表、2–64个人单败/循环、真实路由、卡片连线、完整工程验收。
**Non-Goals:** 组队/瑞士/双败/处罚/时间排程/确认后回滚。
## Decisions
- 独立operations_aggregates(tournamentId,data)持久赛事运行、报名和协作者，旧快照字节与digest不变。运行state版本和layout独立版本；结构编辑仍由现有服务。
- 所有操作同步BEGIN IMMEDIATE事务：真实会话权限→同actor/key请求回放→expectedVersion→领域改变→状态与成功键原子保存；不跨事务调用异步配置服务。
- 开赛绑定冻结快照和runtime-rules-v1，批准个人名单给种子与初始小组，后续来源由既有previewRouting计算真实快照。一次事务应用全部下游就绪结果。
- 单败种子表递归展开[1,2]，8槽[1,8,4,5,2,7,3,6]，直接slot映射沿用物理邻接；轮空生成自动bye标记不计算真实场次。循环固定首位旋转，奇数加空位；一次固定同分集合交手积分，再统计所有正常比赛净胜局，不递归重算小积分，不按ID破同分。
- 明确裁定为推进前提；提交和裁定分别记录；bo偶数比分仅在循环允许平局时接受；双方判负不携带虚假数字。排名阻塞可留已锁赛果，显式排序留理由后执行路由。
- 卡片编辑采用React+SVG，不新增第三方节点运行引擎；具名端口选中连线及下拉等价操作、拖动、缩放、布局保存。表单继续编辑全部结构参数，键盘/触摸均可完成连线。
- 新精准端点先挂载，原501清单排除实际实现的路由；per-tournament runtime状态与全局能力分开。旧研究意图不自动可运行。
- 注销在原事务中删除自有operations聚合，其他赛事移除报名答案/授权，运行名单匿名化保留ID与比分。预览token包含操作聚合版本，避免范围竞争。
## Risks / Trade-offs
[单行赛事聚合竞争] → 2–64人上限、短同步事务、expectedVersion明确409。
[同分与异常] → 明确阻塞与留因裁定，不伪造名次。
[历史不支持模板] → 运行复验支持集，未实现准确501。
## Migration Plan
新增带赛事外键的表，不重写历史配置。备份非临时SQLite；两端配套发布；回退保留新聚合而旧能力不可运行。本轮测试仅临时数据库，未生产部署。

独立赛事初始seed保留绝对序号；阶段内小组按全局种子顺序生成组内序列。公开运行投影去除全部裁定者账号ID。重读版本不卸载赛事表单，比较后由用户选择本地或服务器；原请求重试保留原键和原请求体。
