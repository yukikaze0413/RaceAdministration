# Proposal

## Why

校园网访问时，新建 Match 要等待整图编辑和完整分析响应。此前网络模拟中，新增节点等待约 1.77–1.92 秒。画布需要参考 ComfyUI，把编辑状态与服务端计算分开。

## What Changes

- 把新增、删除、连线、属性、Stage、子图、撤销和重做迁移至浏览器。
- 把普通编辑改为本地操作，移除逐次整图编辑请求。
- 从草稿直接生成端口、连线及选择所需的编辑模型。
- 把结构检查和破坏性操作的影响确认迁移至浏览器。
- 把共享图规则抽成独立模块，后端保存时继续复核。
- 把完整来源分析改为主动触发的草稿分析，不随输入自动请求。
- 保留保存、验证保存版本、读取预览和保存 Session 的服务端流程。
- 增加编辑版本及请求归属检查，阻止旧响应覆盖新草稿。
- 保留预设、属性自动生效、稳定身份和撤销行为。
- 清理旧画布分支，统一使用 canvas、canvas-editor 和 canvas-plan。
- 启动时转换已保存的 canvas-v2 草稿，保留验证、排期及幂等记录。

用户已要求实施本地编辑迁移，并于 2026-10-16 确定清理旧画布及取消版本后缀。实际验收结果见 acceptance.md。

采用先迁移编辑、再解除渲染对分析结果的依赖、最后验收网络隔离的顺序。不引入模型执行、多人协作或自动保存。画布渲染库替换另行评估。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `planning-canvas`：增加本地编辑和结构检查；区分编辑模型、草稿分析与权威验证；补充请求归属、兼容及性能要求。

## Impact

- 前端：planning-canvas 编辑状态、属性、Stage、画布和赛程页面。
- 后端：graph 规则拆分、组件目录、分析接口和兼容编辑接口。
- 共享模块：图结构、原子编辑、端口、边界、规则元数据及影响确认。
- 构建：共享模块的浏览器及 Node.js 入口、声明和测试配置。
- 数据：画布格式统一为 canvas；启动时原子转换已有数据及摘要；保存并发版本继续保留。
- 外部资料：参考官方 ComfyUI 的本地节点创建、工作流序列化及服务端执行分工，详见 design.md。
