## 1. 用户目标与已确认约束

用户本轮提出：
- 模块化、可视化、可操作、可高度自定义的赛事设定。
- 赛程卡片自由组合并连线，可将某循环小组第一名放入某淘汰席位；自由度受赛事规则约束。
- 创建者和管理员分权限编辑赛事参数，参赛者填写可自定义字段的收集表。
- 管理员确认赛果后，按赛果生成下一轮对阵。
- 提供一键调用且可继续编辑的赛制预设。
- 代理自行设定赛事目标，并在实施阶段实际运行与测试。

亲读现有 PRD、SDD、赛制研究、正式规格和关键接口后确认：
- 赛事系列 → 独立赛事 → 阶段 → 轮次/对阵；小组属于阶段，池是跨阶段汇入与重排模块。
- 所有赛制仍遵守整轮收齐 → 有权管理员确认 → 锁定整轮 → 推进；单场提交不提前产生下游对阵。
- 已确认赛果不可修改，本期不提供已推进后的回滚改判。
- 晋级路由在草稿期编辑，开赛前冻结；运行中不改晋级目标。
- 自动时间排程、退出者移出配对、回溯 DQ 后置。
- 双方判负与双败淘汰是不同概念；循环允许双方判负，淘汰禁止。
- 两个持续退出者在淘汰赛相遇的处理仍未决定，不能自动制造胜者或冠军。

上一轮聊天中的“逐场确认即可推进”“确认后直接更正重算”草案与既有决定冲突，本简报撤回这两项。

## 3. 推荐设计与替代方案

推荐：现有领域路由 + 受约束节点编辑器 + 独立赛事运行模块。
另两种方案：仅扩充现有表单，开发成本较低但不能满足连线操作；全新通用节点执行引擎，自由度高但引入与用户需求无关的脚本、任意循环与执行语义。
选择推荐方案的理由：保留已验证的晋级语义、校验和快照；将编辑器交互复杂度与赛制算法隔离。

### 3.1 卡片与连线

阶段容器内展示小组卡片；阶段/池有稳定 ID。循环卡片提供“第1名/第2名”等具名输出端口；淘汰卡片提供具名 slot 输入和只读对阵预览。
连线产生业务 route，标签展示来源、名次、配额及目标席位。seed 与物理 slot 始终分开显示。
淘汰赛内部轮次/比赛由规则生成，作为展开视图，不允许任意改内部胜者边。
画布支持拖动、缩放、平移、定位诊断、选中编辑、显式删除影响提示。移动端和键盘提供等价的连接列表/参数面板；不得把拖拽当唯一编辑方式。
布局单独保存为 editor-layout-v1，按配置 ID/对象 ID 引用，具有独立 expectedVersion；布局变化不改变结构 digest。
未保存结构不得执行旧版本校验/冻结。服务端为唯一合法性裁决；冲突保留本地草稿，显式重读后替换。

### 3.2 权限与收集表

拟采用赛事能力集：
metadata.edit、structure.edit、registrationSchema.edit、registration.review、
results.edit、rounds.confirm；collaborators.manage 仅创建者。
具体命名为设计建议，不是已上线接口。只获报分权不等于推进权；客户端 role/actorId 永远不授予权限；撤权在写事务内复核。
公开赛事、私有赛事、参赛者与协作者分别投影；报名答案默认仅本人及有报名管理权限者可见。

报名 schema 独立于赛事结构，字段使用稳定 ID，拟支持文本、长文本、数字、单选、多选、勾选；可编辑标签、帮助文字、必填、选项、长度/范围与顺序。
发布形成不可变 schemaVersion，报名记录引用提交时版本。已有答案不能因改标签错位或被删除；删除采用停用，改变字段类型创建新字段 ID。
首期建议不做文件上传、条件字段、支付、外部验证、候补和签到；个人/组队范围尚待本轮选择。
报名状态建议 draft → submitted → approved/rejected；同账号同赛事仅一个有效参赛单位。锁定名单后拒绝新审批与改变参赛身份；早期表单改版不能静默让旧有效报名失效。

### 3.3 运行状态与事务

structure-v1 与历史快照保持不变。运行规则 runtime-rules-v1、报名 schema、画布布局分别持久化；开赛生成运行快照，绑定结构 digest、规则版本、名单版本和固定席位。
执行状态建议 registration-open → registration-closed → ready → running → completed；单独记录阶段、小组与轮次状态。
开赛复核人数、唯一身份/种子、初始席位、路由合法性、支持变体与规则参数；结构冻结本身不启用真实运行。
整轮确认在一个 SQLite 事务内检查权限、expectedVersion、完整赛果、冲突及来源就绪，写锁定结果/排名/下一轮或下一阶段/幂等结果。
请求键绑定 actor、赛事、操作及规范化输入；相同键回放相同结果，同键不同输入409；不同键重复确认不生成第二轮。
来源同分未决时可以保存已确认比赛，但输出标为 ranking-blocked；不得伪装为来源完成，不产生部分下游晋级。
单组整轮独立推进、所有必要来源完成后衔接后续阶段，是待本轮选择的方案。
最终轮不创建空下一轮；完成目标输出后展示冠军及赛制定义的并列名次，不自动制造季军。
原始选手提交与管理员裁定分别保留，裁定写入操作者/原因/版本；确认前可修正，确认后拒绝。
处罚新增规则尚未冻结；不以本期普通赛果逻辑暗中实现退出/DQ，现有未决处罚接口仍明确不可用。

## 5. 自主设定的样例赛事与独立预期

以下样例仅为代理自主设定的工程目标，全部“未运行”，不代表真实用户业务接受。
样例赛制以第4节待答范围成立为前提。最终输入/expected 文件由实施阶段保存；expected 不由被测算法生成。

### E1 八人两组循环接淘汰

A组 a1–a4，B组 b1–b4；每组四人单循环三轮六场，共12场。
组内较小编号总以2–0获胜；各组积分为9/6/3/0，唯一排名与编号一致。
手动连线：A1→slot1，B2→slot2，B1→slot3，A2→slot4。
半决赛 a1–b2、b1–a2；a1和b1分别2–0胜，决赛a1以2–1胜b1。
总计15场真实比赛，冠军a1、亚军b1、两名半决赛失败者并列3–4，无季军赛。
分步验证：可编辑预设→保存/刷新连接→发布报名表→8账号填写→审批→种子分组→锁定→开赛→整轮确认→交叉晋级→完赛→重启恢复。
A组提前结束不得单独填入部分B组依赖目标；缺赛果不得推进；重复确认/响应丢失/重启后原键重试仍只有一个下游轮次。

### E2 六人单败与轮空

拟采用版本化 seed→slot 表：8槽种子序列[1,8,4,5,2,7,3,6]，实际只有种子1–6，7/8为空。
首轮：1轮空、4–5、2轮空、3–6。高种子每场获胜，则半决赛1–4、2–3，决赛1–2，冠军1。
5场真实比赛、2个首轮结构轮空；轮空不计正常场次，不要求用户输入虚假比分，不给循环积分。
检查奇数与非二次幂、空空分支、重复种子/slot、配置容量不足及不支持变体开赛拒绝。

### E3 五人单循环覆盖

轮次手写预期：
1 B–E、C–D，A休赛；
2 A–E、B–C，D休赛；
3 A–D、C–E，B休赛；
4 A–C、B–D，E休赛；
5 A–B、D–E，C休赛。
10个无序对各出现一次，每人4场、一次休赛；休赛不计胜场和积分。
较小字母以2–0胜：A/B/C/D/E积分12/9/6/3/0，冠军A。
另设三人各赢一场且比分相同的同分例，预期按选定策略阻塞或加赛，不能按随机数/ID偷偷晋级。

### E4 权限、数据与失败矩阵

仅结果管理员可以裁定、不能改结构/授权/确认；仅报名管理员可以读取收集答案，不能改结果。
参赛者只能提交自己的报名和当前对阵赛果；伪造 actorId、跨赛事/他人rid/mid拒绝。
字段改名/排序/停用保留原答案；发布新必填字段不自动改已审批旧报名。
缺一场、非法比分、未裁定冲突、已锁定改分、重复/并发确认、过期版本、磁盘回滚、撤权竞争分别验证。
画布环、重复slot、越界名次、删除引用、部分来源未齐均有可定位诊断；画布拖动不能改变晋级顺序。
新增关系参与账号删除预览与事务：删除自身报名/授权与当前拥有赛事数据，同时保留他人赛事历史赛果最小身份引用；采用匿名化历史引用的方案须单独评审，不能因新增外键破坏现有注销。
在独立临时 SQLite/临时账号运行，避免演示动作写入用户现有赛事。
