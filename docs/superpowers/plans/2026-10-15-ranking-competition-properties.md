# 淘汰赛 Match、瑞士轮和小组循环赛属性修改计划

日期：2026-10-15。
状态：Match、瑞士轮和小组循环赛的画布修改已完成。

## 1. 目标和组件职责

Match 表示淘汰赛中的单场对决。
瑞士轮和小组循环赛分别管理整段赛制规则。
两者均以 round（一轮对阵）为基础单位。
一个 round 包含该轮的全部对阵及休息名单。
赛制规划、轮次依赖、wave 分配和 session 引用均以整轮为单位。
比赛场数只作统计，不用于划分赛制或拆分基本调度单元。
平局、双方判负、积分和排名归属于赛制。
时间统一由 session 管理。

| 组件 | 输入 | 输出 | 负责的规则 |
|---|---|---|---|
| Match | A、B 单席位 | 唯一胜者 W、唯一败者 L | 单场赛制、轮空 |
| 瑞士轮 | 有序参赛集合 | 全排名集合及种子映射 | 人数、轮数、配对、积分和排名 |
| 小组循环赛 | 一个小组的有序参赛集合 | 全排名集合及种子映射 | 单循环或双循环、对阵、积分和排名 |

平局不产生胜者或败者。
双方判负为双方各记负场，不产生唯一败者。
排名型组件内部不通过 W/L 端口转发这些结果。
Match 保持唯一胜败语义，异常弃权或取消资格另行处理。

## 3. 属性分类与共用结构

### 3.1 全部组件共用

- 名称：可编辑。
- 坐标、ID、所属子图：内部保留，不提供属性输入。
- 端口显隐：保留现有显示设置。
- 参数修改：沿用自动生效、撤销和显式保存。
- 开始时间和时长：不放入赛制属性面板。

### 3.2 排名型组件共用

基础结构共用 ruleVersion、parameters 和排名输出协议。
两种赛制共用 round 规划结构，包含轮次标识、所属组件、轮次序号、容量、对阵和休息名单。
瑞士轮尚未配对时，对阵保留待解析状态，round 仍然存在。
单场对阵属于 round 内部明细，不成为独立的淘汰赛 Match 节点。
瑞士轮与循环赛分别拥有模式专属字段。
共用 UI 负责单场赛制、积分编辑和同分规则编辑。
不得让循环赛继承瑞士轮的配对和胜负阈值逻辑。
暂不扩展当前未使用的 release 字段；旧数据保留读取。

模式、积分、同分顺序和固定项均由规则目录提供。
前端只编辑目录允许修改的字段。
后端保存和验证继续复核，不能只依赖前端禁用控件。

## 5. 瑞士轮属性设计

### 5.1 常用属性

瑞士轮的核心参数为人数、轮数，按此顺序展示。
模式和规则版本不再占据核心参数区，放入高级规则或固定摘要。
人数作为计划容量；连接输入后与集合人数核对，不另造参赛者或截断集合。
输入人数未知时保留计划人数，并标记实际容量待解析。
未连接输入时，可按计划人数预留 round，但不能生成真实对手。
轮数始终表示 round 数量，不表示比赛场数。
固定轮数模式表示计划轮数；阈值模式表示最大规划轮窗口，不能承诺每名参赛者打满。
专用规则固定轮数时，展示规则值，不能提供无效输入。
本期不新增胜场参数或据此提前晋级的行为。
已有阈值及专用规则保留兼容，不因面板精简而删除运行规则。

| 属性 | 固定轮数瑞士 | 胜负阈值瑞士 | 专用规则 |
|---|---|---|---|
| 名称 | 可编辑 | 可编辑 | 可编辑 |
| 人数 | 计划容量，与输入集合核对 | 同左 | 按规则校验容量 |
| 轮数 | 可编辑 | 展示最大规划轮窗口，修改能力由规则决定 | 按规则固定 |
| 单场赛制 | 从规则与共享目录的交集中选择 | 同左 | 固定或受限选择 |
| 允许平局 | 规则允许时可改 | 当前模式禁止，不提供可点击开关 | 按规则固定 |
| 允许选手提交双方判负 | 按现有权限规则显示 | 同左 | 固定禁止时只显示规则摘要 |

“单场赛制”替代面板中的“默认 BO”名称。
旧 BO5、BO7 等值保持兼容，不能静默改成 BO3。
新目录当前只提供 BO1、BO3。

模式切换原子更新规则版本和专属参数。
同一模式可保留仍然合法的公共参数。
不兼容项使用新模式默认值，并保持一次撤销可恢复。
固定规则项在规则摘要中展示，不排列无法操作的表单控件。
TI 候选规则继续标注候选状态，不承诺实际运行能力。

### 5.2 积分和同分顺序

固定轮数模式提供胜、平、负、双方判负的积分设置。
平局关闭时，不提供平局积分输入，旧数值保留以便恢复。
双方判负积分是否可改取决于赛制规则，不取决于选手提交权限。
积分遵守现有 win > draw ≥ loss 约束，并检查整数范围。

胜负阈值模式以战绩为依据，不显示无效的积分表。
同分顺序改为有序列表，支持上移、下移和选择合法规则。
显示名称使用中文，内部规则 ID 隐藏。
固定的首项、末项及专用排序约束由目录检查。
相互战绩、对手积分和对手胜负差不能混用同一个名称。
人工裁定仍是未决排名的处理方式，不能用初始种子伪造裁定。

### 5.3 高级属性

- 瑞士模式及淘汰负场：只在适用规则中显示，不挤占人数、轮数的位置。
- 首轮配对和种子落位：按规则显示固定摘要或受限选择。
- 晋级战、淘汰战赛制覆盖：仅在规则支持时显示。
- 逐轮赛制覆盖：只显示已配置轮次，按需添加和移除。
- 规则版本：显示可理解的规则名称，版本 ID 留作内部数据。
- 排名输出：固定使用完整排名协议，不提供“未配置”选项。

### 5.4 输出与规划边界

保留原 collection、seeds 端口及已有连线。
固定轮数模式按 roundCount 生成整轮占位。
阈值模式按规则生成最大规划轮窗口。
减少轮数不得静默删除旧覆盖，应提示处理或保留为非生效配置。
实际轮空、对手和退出人数继续由正式规则执行时确定。
奇数人数不得显示半场比赛；单独展示轮空和待解析容量。

本期保留全排名输出，不新增自动晋级输出承诺。
固定轮数模式可继续用选择器选取前 N 名。
阈值模式的达标资格不能用“全排名前 N 名”冒充。
若后续需要独立资格输出，须另行确定动态容量和接口协议。

## 6. 小组循环赛组件设计

### 6.1 组件粒度与常用属性

新增一个独立的 round-robin 节点。
一个节点表示一个小组，多个小组通过多个节点及 Stage 组织。
Stage 是执行分组，不能兼作积分小组。
暂不增加一个节点内部再分多组的表单和分组分配器。

| 属性 | 行为 |
|---|---|
| 名称 | 例如 A 组、B 组 |
| 循环方式 | 单循环、双循环，映射已有两个规则版本 |
| 单场赛制 | 规则允许的 BO1、BO3 |
| 允许平局 | 规则允许时可编辑 |
| 允许选手提交双方判负 | 明确为提交权限，不冒充赛果能力开关 |
| 参赛人数 | 从输入集合推导，只读 |
| 循环轮数 | 从人数及循环方式推导，只读；作为规划和调度的基础数量 |
| 预计场数 | 只读统计，放在摘要中 |

输入必须为一个有序参赛集合。
种子顺序保留为对阵和同分规则的来源。
不手填与连线容量重复的 groupSize、groupCount 或轮数。
晋级人数先由下游选择器表达，不再设置第二份前 N 名规则。

### 6.2 积分和排名

积分编辑器与固定轮数瑞士共用，默认值取已有规则目录。
同分列表仅提供循环赛支持的积分、相互战绩、净胜局和人工裁定。
沿用现有同分规则语义，先用独立算例核对。
若发现当前算法与界面规则名称不符，单独修正规则或新增版本。
不得在属性重构中静默改变已冻结比赛的同分处理。
仍有并列时显示待裁定，不输出虚假的唯一排名。

### 6.3 对阵和轮空

复用已有编译器的轮转算法，不另写一套循环赛排程。
单循环中每对参赛者交手 1 次。
双循环中交手 2 次，第二回合反转双方位置。
奇数人数通过每轮休息名单表示，不生成假对手或假比赛。

手写验收算例：

| 人数 | 单循环轮数/实际比赛数 | 双循环轮数/实际比赛数 |
|---|---|---|
| 4 人 | 3 轮 / 6 场 | 6 轮 / 12 场 |
| 5 人 | 5 轮 / 10 场 | 10 轮 / 20 场 |

人数未知时保留容量待定，不显示已确定对阵。
循环赛内部使用 fixture 记录，保存双方来源、轮次和回合。
fixture 不是 Match 节点，不暴露 W/L 端口。

### 6.4 输出、Wave 和 Session

输出先采用 collection 和 seeds，分别表示完整排名及其种子映射。
暂不增加 fixtures、standings、qualification 等图连线类型。
对阵和排名诊断作为分析结果展示，不作为参赛席位端口。
未完成排名使用稳定占位，不能把输入顺序当成最终排名。

每个循环赛轮次形成一个基本调度单元。
瑞士轮也遵守相同的整轮调度规则，不能按该轮比赛数量拆分单元。
后轮依赖前轮完成，wave 由验证统一分配。
新增两种赛制共用的 round 协议，旧瑞士轮 roundIds 通过兼容适配保留。
WavePlan 按 round 引用赛制轮次，另附所属组件、赛制种类及内部 fixture 索引。
具体字段名在契约实施时统一，不分别维护两套轮次调度逻辑。
同步更新 plannerVersion、保存快照及排期失效检查。
Stage、子图归属、人员冲突和全局依赖继续由现有调度器检查。
Session 只引用 wave 并安排时段，不重复维护循环赛轮次顺序。

预览按小组、轮次和回合显示双方来源与休息名单。
循环赛不显示“瑞士轮动态配对”诊断。
没有真实赛果时不生成实际积分和排名表。

## 7. 全局规则与权限的整理

现有 allowPlayerDoubleLoss 继续表示选手提交权限。
若产品需要赛制级 allowDoubleLoss，须新增独立字段和校验。
该调整会涉及配置域、冻结配置、编辑员裁定和运行器。
不能只修改画布 checkbox 标签就宣称已经禁止所有双败结果。
本期先保留准确的权限名称，不擅自扩大为正式赛事规则重构。

平局能力由规则版本决定。
胜负阈值和专用瑞士规则不得被通用开关绕过。
规则目录可增加属性分组、中文名称、固定项和能力元数据。
正式配置、画布和后续共享编辑核心使用同一份约束。
不把 UI 分组属性写入业务 params。

## 10. 已采用的产品边界

已确定：瑞士轮及小组循环赛以 round 为基础单位；瑞士轮核心参数为人数、轮数。

本轮采用以下边界：

1. 一个循环赛节点只表示一个小组。

4. 循环赛内部对阵只作规划，真实赛果仍在正式运行页处理。

如果需要改变任一项，应先更新相应输入、输出和验收规则。
